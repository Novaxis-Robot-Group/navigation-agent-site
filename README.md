# Navigation Agent 官网

面向外部开发者和客户的中英双语产品介绍网站。首页默认英文，右上角可切换中文；重新打开或刷新页面回到英文。包含产品介绍、带关键节点的 MuJoCo 与 Go2 回放，以及项目代码和技术文档入口。

- 在线网站：[Navigation Agent](https://novaxis-robot-group.github.io/navigation-agent-site/)
- 网站源码：[navigation-agent-site](https://github.com/Novaxis-Robot-Group/navigation-agent-site)
- Agent 项目：[navigation-agent](https://github.com/Novaxis-Robot-Group/navigation-agent)

这是独立维护的静态网站，只需浏览器和 Python 3，不依赖 Node.js、Agent 服务或机器人环境。在 Mac 本仓库的 `main` 分支直接开发。

## 本地预览

在本仓库根目录运行：

```bash
python3 preview.py
```

打开 <http://127.0.0.1:4173/#videos>，在首页“视频演示”区域查看任务回放。预览服务支持视频分段读取（HTTP Range），可直接跳转到未播放的节点。普通 `python3 -m http.server` 不支持完整的录像跳转。

页面只保留顶部导航，滚动时始终吸顶显示。章节跳转会避开导航栏；手机换行及语言切换后按实际高度调整。首屏不显示“Watch a search”按钮，不显示左侧目录。任务锚点可直接分享，例如 `/#go2-bin`。

首页按“简短介绍 → From a goal to exploration → See it in action → Benchmarks”组织。效果演示包含 MuJoCo 方法对比和 Go2 真实场景两个小节。MuJoCo 和 Go2 各自按 Task 1、Task 2 等顺序纵向展开全部任务，每项标题显示目标名称，不需要切换任务。桌面左侧为 VLN 回放（未录制任务保留占位），中间为 Agent + VLN 回放，两种方法之间用竖线分隔；右侧常驻 Agent 节点与决策。两个视频等宽、同为16:9。平板将决策放到双视频下方，手机改为上下排列。“篮球”“床”和“冰箱”任务已加入纯 VLN 双视角录像，三项同时展示；各任务支持独立播放、进度、视角切换和倍速。每项的两个倍速选择器分别位于各自播放时间右侧，保持对齐，首次加载默认 4×，录像仅在播放或跳转时加载。卡片不显示顶部状态栏或中央播放提示，使用底部按钮或点击画面播放。短录像结束后停在末帧，另一条继续播放；不拉伸时长或强行对齐事件。Go2 展示同一任务的实拍视角（External camera）、相机视角（Robot camera）与 Agent 节点；已接入“走到银色垃圾桶旁”和“走到茶水间吧台”的双视角录像与复盘节点，两路共用任务时间轴、播放和倍速；实拍未覆盖的时段显示提示。Go2 仅展示这两个任务，已移除饮水机和会议室占位。两个视角合并为左右分屏播放器，共用底部的一套播放按钮、进度条、倍速和全屏；手机也保留左右分屏，节点放在下方。全屏在浏览器支持元素全屏时同时显示双视角；仅支持视频原生全屏的设备回退到机器人相机。不与 VLN 对比。回放采用灰白底与少量低饱和灰蓝选中状态，组件统一为圆角白色卡片，标题和卡片边缘对齐，整个对比区桌面最大宽度为 1240px。节点列表常驻；说明以贴着节点的气泡按需显示。悬停或键盘聚焦可查看，点击节点同时跳转并保持气泡；点击外部、关闭按钮或按 Esc 收起。

确认视频可播放、节点可跳转、切换视角后保留进度，即回放预览成功。修改后刷新浏览器；按 `Ctrl+C` 停止服务。

修改 Go2 播放逻辑后，可用 Node.js 运行 `node --test tests/go2-replay.test.cjs`。测试检查双路缓冲、4× 同步、1× 播放、取消等待和进度跳转。Node.js 仅用于此项开发测试。

首播需在真实浏览器中验证。先启动测试预览：

```bash
python3 tests/playback_preview.py --port 4174 --mbps 8
```

在 Chromium 或内置浏览器中，每轮先打开 `http://127.0.0.1:4174/__cold-start`。此测试入口发送 `Clear-Site-Data` 响应头，清除本地测试站点的缓存与存储。然后点击对应任务链接，立即点击播放并等到结束。Safari 使用全新的私密窗口。两项任务分别清缓存测试。测试预览将所有录像的总带宽限制为 8 Mbps，播放期间允许保存新下载的分段。不能把刷新已播放的页面当作首次访问。

播放结束后，在另一终端读取本轮指标：

```bash
python3 tests/playback_report.py http://127.0.0.1:4174
```

确认两路均开始播放、任务播放到片尾，并检查首次等待时间、播放中等待次数、实拍跳转次数和双路最大偏差。慢网测试可把 `--mbps` 改为 `4`；改变参数后重新启动测试预览。测试脚本与指标不会发布到官网。

## 修改内容

前端风格以 [AGENTS.md 的风格基线](AGENTS.md#前端风格基线2026-10-15-用户确认) 为准：白底与低饱和灰蓝、16px 圆角卡片、细边框与轻阴影、统一对齐。后续扩展沿用这版；具体配色、尺寸、回放布局和双语规则集中维护在该约定中。

- `index.html`：英文正文、`data-en` 英文与 `data-zh` 中文文案、GitHub 和技术文档链接。
- `styles.css`：配色、排版与手机布局。
- `site.js`：全站文案切换。
- `favicon.svg`：浏览器标签页图标。
- `replay.css`、`replay.js`：首页内嵌回放的样式与交互。
- `media/replays/sessions.json`：MuJoCo 任务目录、双语节点说明和录像时间。
- `media/go2/sessions.json`：Go2 两个实机任务的双视角录像、实拍时间偏移与双语节点。

## 网页字体

英文使用 IBM Plex Sans，中文使用思源黑体网页子集。字体放在 `media/fonts/`，随网站部署，不依赖访问者预装或外部字体服务。首次加载采用系统字体过渡；网络失败时继续使用系统字体。

思源黑体原始字库来自 Adobe `source-han-sans` 2.005R，网页子集内部名为 `Nav Han Web`；IBM Plex Sans 使用 Google Fonts v23 的拉丁可变字体。原始许可证随字体保存在同一目录，字体不适用网站源码的 Apache-2.0 许可。

仅更新字库时需要 Python 3.10+。以下 `python3` 应指向该版本。新增页面或任务文案后，在仓库根目录更新中文字形：

```bash
python3 -m pip install --target .runtime/font-tools 'fonttools[woff]==4.67.0'
PYTHONPATH=.runtime/font-tools python3 prepare_fonts.py
```

脚本首次下载原始字体到 `.runtime/fonts/`，之后复用缓存。生成字体文件名包含内容哈希；本地预览和发布工作流也为字体 CSS 添加版本。将 `media/fonts/` 的变化与文案一同提交。只浏览或部署网站不需要安装这些 Python 依赖。

在 `index.html` 的 `#benchmarks` 中维护四行数据：

| 页面名称 | 官方来源 |

| Room-to-Room（R2R） | [Matterport3D Simulator](https://github.com/peteanderson80/Matterport3DSimulator) |
| Room-Across-Room（RxR） | [RxR 数据集](https://github.com/google-research-datasets/RxR) |
| INSIGHT-Bench | [官方项目页](https://lightorigins.github.io/Light-INSIGHT-Bench/) |
| HM3D ObjectNav v2 | [Habitat-Lab 数据集清单](https://github.com/facebookresearch/habitat-lab/blob/main/DATASETS.md) |

表格比较 LightNav 与 Agent + LightNav，列为 SR（百分数）、SPL（0–1）和 LLM-judged SR（百分数）。**所有当前数值均为用户要求的布局示例，不是实测或官方成绩。** 保留表格上方的双语 mock 说明；换入完整实测结果后再移除。同步补充评测版本、split、任务数量和实验设置，不将各基准的分数直接横向比较。R2R / RxR 是否采用连续环境版本尚待确认；HM3D v2 对应官方 `objectnav_hm3d_v2.zip`（HM3DSem-v0.2）。

场景中可能有多个符合指令的同类目标，如椅子、电视或桌子。当 SR 绑定特定标注实例时，其他有效目标可能不计成功；不能将这一限制泛化到所有基准。LLM-judged SR 根据原始指令和最终画面，从语义上补充评估任务是否完成，不替代官方 SR。评审模型须独立于导航 Agent；两组使用同一评审模型、提示词、判定标准与任务集合，以保证比较公平。发布时注明独立评审模型及其设置。不确定计失败并单列，API 错误先补评，不能删除失败任务。R2R / RxR 的过程性要求不能仅靠最终画面判定。

SPL 同时衡量成功与路径效率。探索可能延长路径并导致部分 SPL 下降，但不代表每次下降都来自有效探索。换入实测分数后，结合轨迹说明原因，不根据示例分数下结论。页面将这些必要说明收进“评测口径”。

## 任务回放素材

当前示例来自 2026-10-13、2026-10-16、2026-10-20 的三段 MuJoCo 已完成任务：找到地上的篮球、走到床边、走到冰箱旁边。完成状态来自原始任务日志，不表示独立人工评测。Go2 独立区域仅展开银色垃圾桶与茶水间吧台两个任务，均已接入双视角及节点，共用每项任务的一套播放控件。所有播放器只读取录像，不连接机器人。

每段素材放在 `media/replays/<slug>/`，包含 `first.mp4`、`third.mp4`、起始画面 `poster.jpg` 和最终观察画面 `cover.jpg`。`sessions.json` 中的 `taskId` 可追溯原始任务。只保留展示需要的节点文字和元数据，不复制原始配置、模型请求或环境信息。

节点的 `time` 使用录像秒数。它由事件时间与 `frames.jsonl` 的 `stamp_ns`、`video_s` 对齐得到；相邻采图间隔不超过 0.5 秒时线性插值，其余位置取前一个已保存帧。不能直接把任务耗时作为视频时间。中文说明取自日志，英文说明是精简翻译；节点标题为展示整理。完整录像保持原始内容与速度；精简回放使用下方剪辑记录，动作片段不加速，播放器仍可独立调速。

新增任务时，添加上述素材，并在 `sessions.json` 添加任务和按时间排序的节点。`goalEn`、`labelEn`、`reasonEn` 与中文同步填写。当前页面展示精选关键节点，不是完整日志。`wallDuration` 是任务实际耗时，页面进度显示录像时长 `duration`，两者可能不同。

更新打码素材后，重新生成加速版本，避免发布旧的未打码衍生文件。需要本机安装 FFmpeg：

```bash
python3 prepare_go2.py
```

也可用 `--ffmpeg /path/to/ffmpeg` 指定工具。脚本只读取当前 `sessions.json` 指向的素材，生成 `robot-4x.mp4`、`external-4x.mp4`，并更新内容哈希和来源 SHA256。原速文件、封面、打码和节点时间保持不变。提交前运行回放测试，其中会检查衍生视频是否对应当前原速素材。

播放器默认不自动播放；MuJoCo 仍仅在播放或跳转时加载录像。页面和回放共用右上角的语言切换，选择任务不会改变首页导航锚点。

## 提交和推送

直接在 `main` 修改、预览和检查后，逐项暂存本次文件，再提交并推送到 `origin/main`。网站源码只在本仓库维护，不再同步回 Agent 项目。

## 网站托管

本仓库公开，网站通过 GitHub Pages 托管。推送网站文件到 `main` 后，`.github/workflows/pages.yml` 自动发布；也可以在 GitHub Actions 中手动运行 `Deploy website`。

无需构建。工作流打包首页、对应 CSS/JS、`favicon.svg` 和存在的 `media/`，不将开发说明或本地预览服务作为网页发布。新增运行资源时同步更新工作流的触发路径与打包步骤。

网站仓库公开不改变 Agent 项目仓库的权限。页面中的 GitHub 与文档链接目前指向私有的 Agent 仓库，访问需要权限；Agent 仓库公开后再更新页面提示。网站双语不代表技术文档已翻译。
