Modular architecture, clean boundaries

One agent. Independent adapters for navigation and embodiment.

Adapter interfaces

The Agent uses a shared backend contract. Navigation clients and robot backends are registered independently in the application layer. New protocols require an adapter and validation; this is not zero-configuration compatibility with arbitrary models or robots. Go2's current native service supports LightNav only. MuJoCo is a simulation backend, not a physical robot.

Technical notes

All three animations are conceptual illustrations, not recorded detections, measured trajectories or a complete architecture.

Memory. Observations, object sightings, action results and executed paths inform the current task. This is not cross-task long-term memory or a complete SLAM map. Memory implementation ↗

Monitoring. YOLO-World monitoring is off by default and runs during search navigation when enabled. It requires a detector, streaming observations, target labels and navigation interruption support. Consistent detections across two consecutive frames can interrupt navigation for agent review. Detection alone is not completion; monitoring is inactive during target approach, turning and recovery. Detector guide ↗

Scheduling. VLN executes between planning events such as a candidate detection, stationary motion or a navigation stop. STOP triggers a separate verification request through the same VLM client, using the current stopped image to check target identity, arrival and heading. This task check is distinct from independent experimental scoring. Entry rules depend on deployment; Go2 scene checks can require planning first. No performance gains are implied by the animation. From a goal to exploration

Often, we know what we want to find, but not where it is. Navigation Agent lets robots take on that search. Describe your goal in everyday language, and the robot explores its surroundings without needing you to specify a location or guide it at every turn.

The target may be in another room or around a corner, out of sight. The robot keeps your request in mind as it searches, follows clues it discovers along the way, and approaches possible matches to check whether they meet your requirements. You give it a complete search task, without having to issue a new instruction for each move.

Metrics & evaluation

SR measures task success; SPL also accounts for path efficiency. Exploration can lengthen paths and partly reduce SPL; attribution requires measured trajectories.

A scene may contain multiple valid targets, such as chairs, TVs or tables. If SR is tied to a specific annotated instance, another valid match may not count. LLM-judged SR assesses task completion purely through semantic judgment of the instruction and final image. A separate model, independent of the navigation agent, judges both methods with the same criteria for a fair comparison.

Evaluation splits, episode counts and judge settings will accompany measured results.
